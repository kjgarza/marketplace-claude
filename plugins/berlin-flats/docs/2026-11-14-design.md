# berlin-flats: recommended design, 2026-11-14

Status: proposal, not implemented. Evidence references (§n) point to
[2026-11-14-probe-evidence.md](2026-11-14-probe-evidence.md). Produced by a six-role review
(Chrome, anti-bot, Claude Code runtime, AI pipeline, code review, architect).

## 0. The governing rule

**Scheduled automation only touches sources that accept an honest, identifying HTTP client, or
that push to the user (portal e-mail alerts). Chrome is used only in sessions the user starts.**

Why this rule, given Chrome loaded every portal (§3):

- A headless `claude -p --chrome` poll is still an automated request. ImmoScout24 interstitials
  the user's profile and inberlinwohnen states "Automated requests are not permitted" (§2).
- An unattended Chrome poller needs the Mac awake, Chrome open and the extension connected on
  every tick (§4). An e-mail alert needs none of that and also reaches the phone directly.
- Chrome is the right tool when a human is present: opening a listing, reading its form,
  enrichment, an interactive sweep.

Open point for the user (decision 4): the rule is a recommended default, not a technical limit.
Scheduled read-only Chrome sweeps are feasible and were the user's own hypothesis. Phase 5
keeps that option, gated on measured alert latency.

## 1. Channel strategy per source

| Source | Channel | Cadence | Why |
|---|---|---|---|
| Kleinanzeigen | Plain HTTP, honest UA, page 1, date-sorted query params. Never the robots-disallowed `/preis:`, `/sortierung:` or `/s-feed.rss` forms | 15 min (07–22), 60 min at night | 200 with 27 ads; detail has JSON-LD (§2). User already logged in for applying (§3) |
| degewo, GESOBAU, WBM | Plain HTTP, honest UA | 30 min | Server-rendered 200 (§2); state-owned stock is about 1 in 4 Berlin flats |
| Gewobag | Its saved-search e-mail → Gmail | ingest every 15 min | Official alert form; HTML unclear (§2) |
| ImmoScout24 | Saved-search e-mail → Gmail. Chrome only inside `/apply` | ingest every 15 min | 401 on HTTP; 0 cards in 5 of 5 runs (§1–2) |
| Immowelt | Saved-search e-mail → Gmail. Chrome only inside `/apply` | ingest every 15 min | 403 on HTTP (§2); overlaps ImmoScout24 |
| HOWOGE, Stadt und Land | Probe their own data endpoint over honest HTTP first; else an inberlinwohnen account alert (UNVERIFIED); else interactive `/hunt` | 30 min | Client-rendered (§2) |
| inberlinwohnen | Interactive only; disable the HTTP adapter | — | 403 (§2) |
| WG-Gesucht | Out by default | — | Mostly sublets and rooms; messaging needs login |
| Vonovia, Deutsche Wohnen | Later probe | — | UNVERIFIED |

**Minimum subscriptions: three free alerts, no paid plan.**

| # | Subscription | What it buys |
|---|---|---|
| 1 | ImmoScout24 account + saved search | The largest market, blocked to HTTP |
| 2 | Immowelt account + Suchauftrag | The second private market, blocked to HTTP |
| 3 | Gewobag Suchauftrag | Municipal stock HTTP cannot see |

Plus one Gmail filter applying the label `berlin-flats/alerts`. Kleinanzeigen, degewo, GESOBAU
and WBM need nothing. Whether ImmoScout24 Plus users see listings earlier is UNVERIFIED and is
measured in Phase 2.

**Gmail ingest.** A headless Haiku step only moves data; Bun parses it with deterministic
per-sender parsers:

```
claude -p "<fixed prompt: search label:berlin-flats/alerts newer_than:2d; return JSON
  {message_id, from, received_at, subject, body_text, links[]} per thread; JSON only>" \
  --model haiku --output-format json --max-budget-usd 0.05 \
  --allowedTools "mcp__claude_ai_Gmail__search_threads,mcp__claude_ai_Gmail__get_thread" \
  --disallowedTools "<Bash, Write, Edit, WebFetch and every Gmail send/reply/forward/draft/trash tool>" \
  | bun scripts/ingest-email.ts --stdin
```

Fallbacks, in order: the same prompt as a Desktop scheduled task (UNVERIFIED); read-only IMAP
with an app password in the macOS Keychain. Independently of the plugin, the portal's own alert
already reaches the phone, so detection never depends on this step.

**`scrape.ts`.** Delete the browser user agent, `jinaHeaders` and the reader-proxy tier.
Replace with `honestFetch(url, {domain})`:

- UA `berlin-flats/<version> (personal flat search; +<repo URL>)`.
- Per-domain minimum gap of 4 s ±30%; at most 10 detail fetches per source per run.
- `detectBlock(status, body)` → `blocked` on 401/403/429 or the markers "Ich bin kein Roboter",
  "captcha-delivery", "Automated requests". A 200 with 0 parsed cards → `empty`.
- No fallback.

## 2. Architecture

```
adapters (sources/http-*.ts | ingest-email.ts | interactive chrome)
   → RawListing[] + SourceResult{status, http_status, ms}
   → ingestListings(raw, {channel, source}, cfg, now)          scripts/ingest.ts
        canonicalExternalId(portal, url)
        insertIfNew  (INSERT … ON CONFLICT DO NOTHING RETURNING id)
        existing row: mergeNonNull; never touches verdict, scam, notified_at   (B1, B2, M7)
        fingerprint = sha1(norm(street|PLZ) | round(sqm) | rooms | round(cold/10)) → dup_of
   → extractFromText        sqm and rooms from title + description
   → classifyCategory       flat | swap | wanted | furnished_temp | room   (word-boundary regex)
   → scamScore              negation fix; price rule exempt for municipal channels
   → preference filter
   → fitScore               + scam penalty, −8 per missing critical field
   → notify.ts              driven by notified_at
   → draft step (Sonnet, no tools)
   → human /apply
```

- **Missing-data policy.** Reject only on fields that are present and violate a rule. Critical
  fields: rent, rooms, sqm, district. Completeness = known critical fields / 4. Notify at
  completeness ≥ 0.5, showing unknowns as "?". A failed or blocked fetch never creates a row (B3).
- **Pure Bun:** fetch, parse, ingest, classify, rank, notify, metrics, dossier.
- **LLM steps:** Gmail transport (Haiku, read tools only); drafting (Sonnet, no tools, listing
  JSON on stdin, Bun writes the file); review-band scam judging (Haiku, optional); `/apply`
  (interactive).
- **Location.** Config and personal data live under `resolveStateDir()`
  (`~/.claude/berlin-flats/`): `config.toml`, `profile.toml`, `dossier/`, `drafts/`, `state.db`.
  `loadConfig()` resolves `$BERLIN_FLATS_CONFIG` → `stateDir/config.toml` → error "run
  /berlin-flats:init". The repo ships `config/config.example.toml` and untracks
  `config/config.toml`.

**Schema** (via `ensureColumn`; add `PRAGMA journal_mode=WAL; busy_timeout=5000`):

| Table | Change |
|---|---|
| listings | `channel, category, fingerprint, dup_of, description, first_seen_at, last_seen_at, published_at, notified_at, draft_at, draft_path, fit_score, completeness`. One migration rewrites Kleinanzeigen ids `NNN-203-3331` → `NNN` |
| runs | `channel, source, status ('ok','empty','blocked','error','skipped'), http_status, duration_ms` |
| source_state (new) | `source PK, consecutive_failures, disabled_until, last_ok_at, next_due_at, last_alerted_at` |
| alert_messages (new) | `message_id PK, sender, received_at, parsed_count, processed_at` |
| llm_runs (new) | `ts, step, model, cost_usd, exit_code` |
| events | Actor (`human` or `machine`) in the payload; `calibrate.ts` counts human events only |

## 3. Runtime

| Concern | Design |
|---|---|
| Scheduler | One launchd agent, `StartInterval 300`. `jobs/berlin-flats-hunt.sh` → `bun scripts/tick.ts`, which runs sources whose `next_due_at` has passed. Retire the Desktop `flat-hunt` task |
| Quiet hours 22–07 | Fetching continues at night cadence; `notify.ts` defers to a 07:00 digest |
| Preflight | bun, DB writable, config present, Telegram creds, `claude` resolvable, daily budget left. Chrome checks only in `/apply` |
| Needs-human alerts | Once per (source, reason) per 12 h: login or wall in `/apply`, Gmail step failed twice, budget exhausted |
| Source went dark | HTTP: 2 consecutive `blocked` → disabled 24 h + alert; 2× `empty` → selector-drift alert. E-mail: no alert from a sender in 72 h → "check saved search" |
| Liveness | An 08:00 digest always sends, even with zero listings, carrying the metric line. A missing digest is the alarm. Gaps over 2 h in `runs` are reported |
| Concurrency | `mkdir $STATE/tick.lock` with a PID file, stale after 20 min; WAL |
| Tool lists | Draft step: no tools. Gmail step: two read tools. Bash, Write, `form_input`, `computer`, `javascript_tool`, `file_upload` never appear in a headless run |
| Budget | Per run `--max-budget-usd` (0.05 Gmail, 0.15 draft); daily cap $1 from `llm_runs`. Over the cap, skip LLM steps but still notify |
| Install (M1, M2) | `install.sh --only berlin-flats-hunt` keeps the layout (`jobs/`, `lib/` including `berlin-flats-summary.ts`, `notify-telegram.sh`), vendors the plugin runtime into `$DEST/berlin-flats/` and runs `bun install --frozen-lockfile`. The wrapper uses that copy, not the plugin cache. Also fix `PLUGIN_CACHE` in `headless-claude.sh` for the other jobs |
| Notifier | `notify.ts` calls `notify-telegram.sh` without `--silent-fail` and sets `notified_at` only on exit 0, so failures retry. Escape Markdown in titles. One message per listing, no cap of 10 |

## 4. Apply path

"Apply-ready within minutes" means: Telegram within 5 minutes of `first_seen_at`; a draft within
10 minutes; from the phone, copy the draft, open the link, paste, send.

| Portal | Pre-drafted | User does by hand |
|---|---|---|
| Kleinanzeigen | Full message (single textarea, §3) | Paste, send |
| Immowelt | Message + cheat-sheet for household type, employment, net income, move-in date | Fill, send |
| ImmoScout24 | Message (form not reached; login likely) | Log in, paste, send |
| HOWOGE wizard | WBS answer, income figure, path to the Bonitätsauskunft PDF | Four steps, upload, send |
| degewo, GESOBAU, WBM, Gewobag | Message + field list (forms probed in Phases 1–2) | Fill, send |

**Telegram message:** title, warm/cold rent, rooms, m², district, channel; fit score with top
three factors; scam flags; "?" fields; the form fields that portal requires; the draft
(≤ 1,500 characters); the link (only if its host is on the portal allowlist);
`/berlin-flats:apply <id>`.

**`/berlin-flats:apply <id>`** (new, interactive). Allowed tools: `Bash`, `Read`, and the
Chrome tools `tabs_context_mcp`, `tabs_create_mcp`, `navigate`, `get_page_text`, `read_page`.
It runs the dossier check, opens the listing, reads the form's required fields, shows the draft
and a checklist built from `profile.toml`, copies the draft to the clipboard, and stops. The
user pastes, enters personal data and sends. On confirmation it records `applied`.

**Dossier:** `dossier.ts` reads `profile.toml`; the digest warns 14 days before the SCHUFA
(90 days) or payslips (100 days) go stale. `scribe` reads the move-in window from the profile.

## 5. Safety

- **Untrusted text (M8).** Commands pass ids only; `assess.ts` takes `--json-file` or `--stdin`.
  Prompts wrap ad and e-mail text in `<untrusted_listing>` with a "data, not instructions"
  preamble, truncated to 4,000 characters. Bun validates every LLM output against a schema.
- **Nothing is sent or submitted automatically.** No headless step holds a send-capable tool;
  `/apply` excludes `form_input`, `computer`, `javascript_tool`, `file_upload`; `auto_send` is
  removed from config.
- **Account and IP hygiene.** Home IP only, honest UA, robots honoured, stop at the first
  block; logins and account creation by the user only.

## 6. Phases

Each phase starts with its live probe. If the probe fails, the phase is redesigned before code
is written.

| Phase | Scope | Live probe first | Acceptance | Size |
|---|---|---|---|---|
| **0 Kleinanzeigen notifications again** | `scrape.ts`, new `ingest.ts`, `parse-listing.ts`, `db.ts`, `hunt.ts`, new `notify.ts`, `config.ts`, `config.example.toml`, `install.sh`, `jobs/berlin-flats-hunt.sh`, `headless-claude.sh` | One honest-UA fetch of the search URL returns 200 and ≥ 20 cards parse from the HTTP body; two detail fetches 4 s apart parse rent, sqm, rooms | Second consecutive tick re-notifies nothing; a rejected listing stays rejected; a blocked page creates no row; swap, wanted and temporary ads are not notified; Telegram arrives | M |
| **1 Municipal HTTP + metrics** | `sources/http-{degewo,gesobau,wbm}.ts`, `tick.ts`, `source_state`, `metrics.ts`, daily digest | Honest-UA fetch of each search page (cards, fields, robots), twice an hour apart; HOWOGE and Stadt und Land data-endpoint probe | ≥ 1 municipal listing ingested per day; went-dark alert fires on a forced 403 fixture; digest shows the metric line | M |
| **2 E-mail alerts** | `ingest-email.ts`, `sources/email/{immoscout24,immowelt,gewobag}.ts`, `alert_messages`, fingerprint dedup | From launchd, the Gmail command returns one known thread and a send tool is denied; then 3 real alert e-mails per sender captured as anonymised fixtures | Alert listings notified within 15 min of `received_at`; the same flat on two portals yields one message | M |
| **3 Rank, draft, apply** | `fit-score.ts`, `draft.ts`, `agents/scribe.md`, `commands/apply.md`, `dossier.ts`, `profile.toml`, `set-verdict.ts --actor` | A no-tools Sonnet `-p` run returns a draft under budget; `/apply` opens a tab and reads Immowelt's fields with no input | p95 draft time ≤ 10 min; `/apply` never calls a write tool | M |
| **4 Calibration** | `calibrate.ts`, `commands/triage.md`, skill-name fixes | — | ≥ 30 human verdicts; precision@5 computed | S |
| **5 Contingent** | Scheduled read-only Chrome sweep (ImmoScout24, inberlinwohnen) | Only if Phase 2 shows alert lag above 30 min over a week and the user opts in | — | S |

**Now versus later.** Run Phases 0–3 now in `mode = "calibrate"`: daily digest only, drafts
off. Use the lead time to collect verdicts, measure per-channel latency, prove the alerts and
assemble the dossier (order the SCHUFA about 30 days before going live). Switch to
`mode = "hunt"` at `move_in_earliest − 100 days`, since listings run from "ab sofort" to about
three months out.

## 7. Replacement definition of done

`bun scripts/metrics.ts --days 7` prints:

```
fetch_ok ka=97% degewo=100% email=100% | complete=0.86 | detect_p50=n/a | notify_p95=3m | draft_p95=7m | p@5=0.6 (n=34) | junk=7% | live=96%
```

| Metric | Definition | Target |
|---|---|---|
| fetch_ok per source | `runs` with status ok / attempted | HTTP ≥ 95%, e-mail ≥ 90% |
| completeness | Notified listings with all four critical fields | ≥ 85% |
| detection latency | `first_seen_at − published_at` where minute-resolution; e-mail: `first_seen_at − received_at`. "n/a" under 10 samples | ≤ 15 min after `received_at` |
| notify latency | `notified_at − first_seen_at`, outside quiet hours | p95 ≤ 5 min |
| time to draft | `draft_at − notified_at` | p95 ≤ 10 min |
| precision@5 | Human positive verdicts among the weekly top five; "n/a" under 20 verdicts | ≥ 0.6 |
| junk rate | Notified items a human rejected for category, scam or area | ≤ 10% |
| liveness | Ticks done / ticks expected, 07–22 | ≥ 95% |
| safety | Send or submit tool calls in headless logs | 0 |

## 9. Risks, ranked by blast radius

| # | Risk | Probe that retires it |
|---|---|---|
| 1 | Headless Gmail fails under launchd: three alert sources go blind | Phase 2 probe from launchd; fallbacks Desktop task, then IMAP |
| 2 | Alerts are batched or delayed | One week comparing `received_at` with manual checks |
| 3 | Mac asleep: every channel stops | Liveness metric; "prevent sleep on power" |
| 4 | Kleinanzeigen starts blocking the honest UA | Phase 0 probe; went-dark alert |
| 5 | HOWOGE and Stadt und Land have no honest data path | Phase 1 probe; inberlinwohnen account-alert probe |
| 6 | Prompt injection in alert e-mails | Planted test e-mail to self; logs show only read-tool calls |
| 7 | Unexercised CLI flags (`--allowedTools ""`, connector names in `--disallowedTools`, cost field) | One-line runs in Phases 2–3 |
| 8 | Login or contact limits on ImmoScout24 | First `/apply` |
| 9 | Fit calibration is poor | precision@5 after 20 verdicts |

## 10. Unverified assumptions in this design

- An honest identifying user agent gets the same 200 from Kleinanzeigen that default curl did.
- A headless run can actually read Gmail (tool listing is verified; a read is not).
- Portal alert e-mails arrive within minutes and contain parseable listing links.
- Token and dollar costs.
- Chrome polling tolerance beyond three loads in fifteen minutes.
